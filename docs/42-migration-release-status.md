## Production Baseline Data Migration

Snapshot: 2026-08-25

The legacy production Django service was treated as read-only source of truth.
The export was captured from `api.maxsmartwms.online` and stored outside Git in
`/private/tmp/greaterwms-production-export-20260825.json` with mode `0600`.
The migration plan and SQL were generated by
`tools/migrate_legacy_django_export.py`; the plan was first executed with a
rollback-only dry run and then applied in one transaction to Render Postgres
`WMS-VM`.

Imported into the new tenant `PEAKSMART` (`Peak Smart Logistics`):

- `1` warehouse, `2` clients (`56315` Delta and `50895` PYTES), `2` staging zones, and `40` staging locations;
- `271` SKUs with inches/pounds converted to centimeters/kilograms; original values and source metadata remain in `skus.attributes`;
- `1` pre-arrival inbound order (`ASN202608191`) with container reference `TRHU4217950`;
- `0` inventory rows, matching the production source (`stock` was empty);
- user accounts were not copied or reset; the target database still requires an explicit target admin bootstrap.

The six legacy source-evidence records are preserved as migration metadata and
in the private export backup; the current FastAPI schema does not yet expose a
first-class legacy source-evidence table. No writes were made to the legacy
production database, and the target migration uses deterministic IDs and
insert-only conflict behavior so it can be safely re-run or rejected.

### Current production path

The production DNS is still:

- Frontend: `https://app.maxsmartwms.online` (existing Vercel deployment)
- API: `https://api.maxsmartwms.online`

The API DNS currently resolves to `greaterwms-production.onrender.com`, which
is still the legacy Django service on branch `codex/cli-install-info`. The
frontend and API therefore remain a matched legacy pair. They must not be
replaced independently with the migrated FastAPI/React pair.

Production cutover is intentionally pending a combined plan for:

1. database schema/data migration and backup;
2. new Render production service configuration and secrets;
3. new Vercel frontend deployment with the matching API base URL;
4. browser and API smoke tests; and
5. DNS/custom-domain cutover and rollback verification.

This is a deliberate hold, not an unpushed code change. The migrated code is
already pushed and running in staging.
